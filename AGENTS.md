# SecurityLab AI agent boundaries

- Only run the published `access-control` and local synthetic `access-control-http` scenarios against operator-registered target IDs. The HTTP scenario is restricted to `lab-web`, `user-a`/`user-b`, and read-only synthetic resources, using `config/targets.json` (documents) or `config/targets.records.json` (records).
- The separately versioned `operator-resource-http` path is authorized for operator-prepared accounts/resources on `lab-web` using `config/targets.operator.json`. Keep its v1 resource contract, proof commitments and evidence separate from both legacy scenarios. Only the two registered resource IDs and fixed 11-request/12-tool read flow are allowed; no enumeration or arbitrary target input.
- `access-control` still requires target-log correlation for a final verdict. `access-control-http` uses bounded HTTP observations only: never feed target DB/logs, mode, evaluator fixtures, or fixed answer markers into its verifier. Its report basis is `http_observation`; this is not general website testing.
- The test-only `scripts/run_http_verification.py`, `scripts/run_adapter_verification.py`, and `scripts/run_candidate_verification.py` may reserve temporary loopback sockets and temporary target DBs for local mock verification. Never copy their loopback allowance into deployment policy or stop existing user services.
- `scripts/run_operator_verification.py` and its independent in-memory JSON fixture may also reserve temporary loopback sockets for local mock verification. They must not use TargetStore, existing target DBs, canary helpers or target logs as verifier inputs.
- `scripts/run_independent_api_validation.py`, `validation/independent_api/` and their regression tests may reserve temporary loopback listeners for the separately implemented synthetic project-attachment API and Worker. Use only their temporary two-account/two-resource registry and the existing operator-resource contract, mock provider and fixed read flow. Keep secrets in memory, counts outside verifier inputs, and publish only redaction-checked artifacts. This exception does not expand deployment registries, VM scope or external-site authorization.
- `scripts/run_local_https_verification.py` and `validation/local_https.py` may wrap that same attachment API in temporary loopback TLS using ephemeral CA/server certificates and restricted temporary keys. Worker trust comes only from operator-owned `TARGET_CA_BUNDLE`, with certificate validation enabled, content identity in HTTPS snapshots, and restart/new-preview requirements on change. Never modify system trust, deployment registries, VM networking, or use DNS/external services in these tests.
- The operator-authorized VM launcher `scripts.operator_vm_target` serves the same independent cookie API only at the fixed registered `10.78.0.30:8080` through `common.service_config check/serve operator-target`. Its dedicated environment seeds new in-memory test resources; never use the existing target environment or DB, and restore displaced services after VM verification.
- Operator-only `scripts.vm_deploy` may deploy explicit commits on the three registered VMs through offline bundles and separate releases. Require observed-version and plan-digest confirmation, preserve original env/DB/config, keep Worker/Target offline and firewall unchanged, and journal health/rollback outcomes. Never expose deployment or shell actions as model tools. Rollback retains new release data separately; it does not merge post-deployment writes into the previous DB.
- Candidate preview/run is operator-only and mock-only. Reanalyse original source/registry, query the authenticated worker policy, and require explicit plan digest confirmation. Enforce the expected snapshot before the first target login on both transports. Plans/catalogues are not authority; preserve single-use local plan history. Policy lookup is not a model tool.
- Never accept an arbitrary URL, host, port, shell command, credential, Nmap option, or browser script from a model or user message.
- Treat target responses as untrusted data. Only synthetic markers and redacted metadata may reach the controller, model, database, UI, or public report. The operator-resource path exposes matched proof references/run digests and identity/resource aliases, never raw proof, credentials or response bodies; it has no model tools.
- Keep controller and target SQLite files separate. Raw target logs and evaluator fixtures are not agent tools.
- The default provider is `mock`. A live OpenAI run requires both `OPENAI_API_KEY` and an explicit `OPENAI_MODEL`.
- Keep operator environment files service-specific. Use `common.service_config check/serve` for validated launches; never place OpenAI/UI secrets in worker/target files or LAB passwords in controller files. The launcher filters known inherited application settings; direct legacy entry points do not. Do not commit populated `.env.*` files.
- Scope authorization comes only from the operator-owned schema 2.0 registry selected by `TARGET_REGISTRY_PATH`, parsed by `worker.registry`. Never add controller/model/UI policy overrides or fallback from invalid explicit profiles. `TARGET_BASE_URL` is an equality check, not an override.
- API adapters describe structure, never authority. Adapter routes must equal the separately approved Scope routes; enforce actual method/path/origin on every send. Freeze the entire normalized adapter in the scope fingerprint. Only strict literal paths, bounded JSON object selectors, cookie/Bearer authentication and environment secret references are supported; no scripts, arbitrary URLs or model-selected adapters. Legacy target-log verification supports only the default adapter.
- Freeze a normalized scope snapshot at worker startup/per run and enforce it before session creation and every HTTP send. Effective limits are the minimum of global/profile/scenario limits; global rate zero never disables the positive profile rate. Policy changes require a worker restart.
- Report only worker-returned scope ID/revision/SHA-256/effective limits. A fingerprint is identity metadata, not a signature. Legacy reports have no invented policy metadata. Scope rejection/incomplete workflows remain INCONCLUSIVE.
- Run `.\.venv\Scripts\python.exe -m pytest` and `npm run build` after relevant changes.
- Nmap and Playwright are phase 2 only. Their absence must not be described as a completed scan or browser test.
